### 6. Функции

#### Контекст

При использовании разных нотаций функций теряется общая стилистика кода. Кроме того, при использовании нотации `function` могут возникать ошибки из-за особенностей её поведения (в частности, динамического `this`).

#### Решение

Для всех React-компонентов, утилит, а также хуков используем **стрелочную нотацию**. Тело компонента и хука всегда записываем в фигурных скобках с явным `return`, даже если оно состоит из одного выражения. Утилиты и колбэки могут использовать краткую запись.

```tsx
import {useState} from 'react';

// ✅ React-компонент
export const UserName = ({user}: UserNameProps) => {
  return <span>{user.name}</span>;
};

// ✅ хук
export const useToggle = (initialValue = false) => {
  const [value, setValue] = useState(initialValue);
  const toggle = () => setValue(prev => !prev);

  return [value, toggle] as const;
};

// ✅ утилита
export const double = (x: number) => x * 2;
```

##### Тело компонентов и хуков: фигурные скобки и `return`

```tsx
// ❌ краткая запись: чтобы вычислить что-то перед разметкой, обёртку придётся переписывать
export const UserName = ({user}: UserNameProps) => <span>{user.name}</span>;

// ✅ тело в скобках: новая строка добавляется без переписывания остального
export const UserName = ({user}: UserNameProps) => {
  const fullName = formatFullName(user);

  return <span>{fullName}</span>;
};
```

- Компоненты и хуки со временем обрастают логикой, и переход от краткой записи к блоку каждый раз даёт лишний шум в диффе.
- Все компоненты и хуки выглядят одинаково, их проще читать и проще искать `return` с разметкой.
- Утилиты остаются короткими: у чистой функции в одно выражение обычно нет причин расти.

##### Обоснование

**1. Стрелочная функция не создаёт свой `this`, а берёт его из окружающего scope**

```js
class Counter {
  count = 0;

  // ❌ function — у колбэка свой this, он уже не экземпляр Counter
  incrementBroken() {
    setTimeout(function () {
      this.count++; // this — не Counter (в браузере это window), count не изменится
    }, 100);
  }

  // ✅ arrow — this тот же, что и в методе
  increment() {
    setTimeout(() => {
      this.count++; // работает
    }, 100);
  }
}
```

**2. Короче и читаемее**

```js
// function
const double = function (x) {
  return x * 2;
};

// arrow
const double = x => x * 2;
```

```js
// ✅ arrow
users.filter(u => u.active).map(u => u.name);

// ❌ function
users
  .filter(function (u) {
    return u.active;
  })
  .map(function (u) {
    return u.name;
  });
```

**3. Нет собственного `arguments` и нет «поднятия» (hoisting)**

Стрелочная функция записывается в переменную через `const`, поэтому до строки объявления она недоступна. Это заставляет писать код в порядке объявления, что уменьшает количество неявных багов.

```js
hello(); // ⚠️ работает, т.к. function поднимается — нарушение порядка легко не заметить
function hello() {}

greet(); // ❌ ReferenceError: Cannot access 'greet' before initialization
const greet = () => {};
```

#### Когда НЕ стоит использовать стрелочные функции

```js
// ❌ методы объекта — this будет не тем
const obj = {
  name: 'test',
  greet: () => console.log(this.name), // this из внешнего scope, а не из obj!
};
```

```js
// ❌ конструкторы — стрелки нельзя вызывать с new
const Person = () => {};
new Person(); // TypeError: Person is not a constructor
```

```js
// ⚠️ методы классов, если нужен полиморфизм/прототип
class A {
  method() {} // лучше обычный метод: он лежит в прототипе и переопределяется в наследниках
}
```

```js
// ⚠️ когда нужен arguments
function sum() {
  return [...arguments];
}
// в новом коде обычно достаточно rest-параметров: const sum = (...args) => args;
```

#### Контроль

```js
// eslint.config.js (фрагмент; добавляется к селекторам правила no-restricted-syntax)
'no-restricted-syntax': [
  'error',
  {
    selector:
      "VariableDeclarator[id.name=/^[A-Z][a-z]/] > ArrowFunctionExpression[body.type!='BlockStatement']",
    message: 'Тело компонента пишем в фигурных скобках с явным return (ADR 6).',
  },
  {
    selector:
      "VariableDeclarator[id.name=/^use[A-Z]/] > ArrowFunctionExpression[body.type!='BlockStatement']",
    message: 'Тело хука пишем в фигурных скобках с явным return (ADR 6).',
  },
],
```

Правило смотрит на имя: `PascalCase` — компонент, `useXxx` — хук. Остальные стрелочные функции под него не попадают.

#### Последствия

- Единообразие кода и подходов
- Более компактная запись, легче читается
- Пишем код в порядке объявления
- Простые компоненты занимают чуть больше строк, зато вычисления в теле добавляются без переписывания
