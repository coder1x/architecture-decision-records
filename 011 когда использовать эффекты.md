### 11. Когда использовать эффекты в React, а когда нет

#### Контекст

Эффекты (`useEffect`, `useLayoutEffect`) задуманы как способ **синхронизировать компонент с системой вне React**: подписаться на событие браузера, запустить таймер, подключить стороннюю библиотеку. На практике их часто используют как универсальное «когда X изменилось, сделай Y». Из-за этого в коде появляются:

- лишние рендеры: эффект запускается после отрисовки, ставит состояние, и компонент рисуется ещё раз;
- цепочки эффектов, где каждый меняет состояние для следующего, и порядок выполнения сложно отследить;
- гонки при загрузке данных и «устаревшие» ответы;
- ошибки, которые проявляются только в Strict Mode, где React в режиме разработки намеренно запускает эффект дважды, проверяя, что он корректно подключается и отключается;
- компоненты, которые React Compiler не может оптимизировать.

Большинство таких эффектов не нужны: то же самое делается проще и надёжнее без них.

#### Решение

**Эффект используем только для синхронизации с внешней системой**, то есть с тем, что находится вне React и не управляется его состоянием: события `window`, таймеры, соединения, сторонние библиотеки, DOM-операции, которые нельзя выразить декларативно. Если внешней системы нет, эффект не нужен.

##### Как понять, нужен ли эффект

Прежде чем писать эффект, отвечаем на вопросы по порядку:

1. **Это можно вычислить из props или состояния?** Считаем прямо в рендере.
2. **Это реакция на действие пользователя** (клик, ввод, отправка формы)? Это обработчик события.
3. **Это данные с сервера?** Используем RTK Query (ADR 2).
4. **Нужно сбросить состояние при смене сущности?** Используем `key`.
5. **Есть внешняя система, с которой нужно синхронизироваться?** Только тогда эффект.

| Задача | Решение |
| --- | --- |
| Вычислить значение из props или состояния | считаем в рендере |
| Сбросить состояние при смене `id` | `key` на компоненте |
| Ответить на клик, ввод, отправку формы | обработчик события |
| Передать изменение родителю | вызвать `onChange` в обработчике |
| Загрузить данные с сервера | RTK Query (ADR 2) |
| Показать значение из внешнего хранилища | `useSyncExternalStore` или хук библиотеки |
| Одноразовая инициализация приложения | вне компонента, в точке входа |
| Подписка на событие `window`, таймер, WebSocket, сторонний виджет | `useEffect` с cleanup |
| Замерить DOM до отрисовки | `useLayoutEffect` |

##### Когда эффект НЕ нужен

```tsx
// ❌ лишнее состояние и лишний рендер: значение можно вычислить
const [fullName, setFullName] = useState('');
useEffect(() => {
  setFullName(`${firstName} ${lastName}`);
}, [firstName, lastName]);

// ✅ считаем в рендере
const fullName = `${firstName} ${lastName}`;
```

```tsx
// ❌ сброс состояния при смене пользователя: сначала рисуется старый комментарий, потом сбрасывается
useEffect(() => {
  setComment('');
}, [userId]);

// ✅ при смене key React создаёт компонент заново, состояние сбрасывается само
<Profile key={userId} userId={userId} />;
```

```tsx
// ❌ реакция на действие пользователя через состояние и эффект
useEffect(() => {
  if (isSubmitted) {
    showNotification('Заказ оформлен');
  }
}, [isSubmitted]);

// ✅ действие обрабатывается там, где оно произошло
const handleSubmit = async () => {
  await saveOrder(order);
  showNotification('Заказ оформлен');
};
```

```tsx
// ❌ изменение передаётся родителю через эффект: лишний рендер и непредсказуемый порядок
useEffect(() => {
  onChange(value);
}, [value, onChange]);

// ✅ родитель уведомляется в том же обработчике, где меняется значение
const handleChange = (nextValue: string) => {
  setValue(nextValue);
  onChange(nextValue);
};
```

```tsx
// ❌ загрузка данных вручную: гонки (ответ на старый userId может прийти позже), нет кэша, нет отмены
useEffect(() => {
  fetch(`/api/users/${userId}`)
    .then(response => response.json())
    .then(setUser);
}, [userId]);

// ✅ RTK Query: кэш, отмена, состояния загрузки и ошибки из коробки (ADR 2)
const {data: user, isLoading} = useGetUserQuery(userId);
```

```tsx
// ❌ ручная подписка на внешний источник ради значения, которое нужно показать
const [isOnline, setIsOnline] = useState(navigator.onLine);
useEffect(() => {
  const update = () => setIsOnline(navigator.onLine);
  window.addEventListener('online', update);
  window.addEventListener('offline', update);
  return () => {
    window.removeEventListener('online', update);
    window.removeEventListener('offline', update);
  };
}, []);

// ✅ useSyncExternalStore: React сам следит за согласованностью значения
const subscribe = (callback: () => void) => {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
};

export const useOnlineStatus = () => useSyncExternalStore(subscribe, () => navigator.onLine, () => true);
```

```ts
// ❌ одноразовая инициализация приложения в эффекте компонента:
// в Strict Mode выполнится дважды, а при перемонтировании компонента — снова
useEffect(() => {
  initAnalytics();
}, []);

// ✅ вне компонента, в точке входа (например, main.tsx)
initAnalytics();
```

```tsx
// ❌ значения формы и ошибки синхронизируются вручную через эффекты
// ✅ используем react-hook-form (ADR 4); для подписки на значение — useWatch
```

Две связанные записи состояния (`useState` + `useEffect`, который обновляет второе по первому) заменяем одним состоянием: второе значение вычисляем из первого.

##### Когда эффект нужен

Подписка на событие, значение которого не нужно показывать, а нужно лишь выполнить действие:

```tsx
useEffect(() => {
  const handleKeyDown = (event: KeyboardEvent) => {
    if (event.key === 'Escape') onClose();
  };

  window.addEventListener('keydown', handleKeyDown);

  return () => window.removeEventListener('keydown', handleKeyDown);
}, [onClose]);
```

Соединение, которое живёт, пока компонент на экране:

```tsx
const [lastMessage, setLastMessage] = useState<string | null>(null);

useEffect(() => {
  const socket = new WebSocket(url);
  socket.addEventListener('message', event => setLastMessage(event.data));

  return () => socket.close();
}, [url]);
```

Сторонняя библиотека, которой нужен DOM-контейнер (пример с графиком см. в ADR 10).

Замер DOM до того, как браузер отрисует кадр, чтобы не было мерцания:

```tsx
// useLayoutEffect выполняется до отрисовки
useLayoutEffect(() => {
  if (!element) return;

  const width = element.getBoundingClientRect().width;
  // eslint-disable-next-line react-hooks/set-state-in-effect -- замер должен попасть в первый кадр
  setWidth(width);
}, [element]);
```

Действие, которое нужно потому, что компонент показан на экране, а не из-за клика:

```tsx
useEffect(() => {
  trackPageView(pageName);
}, [pageName]);
```

##### Правила написания эффекта

1. **Один эффект — одна цель синхронизации.** Независимые задачи разносим по разным эффектам, у каждого свои зависимости.
2. **Зависимости указываем честно.** Правило `react-hooks/exhaustive-deps` не отключаем. Если зависимость «мешает», это признак того, что эффект не нужен, либо нужно отделить нереактивную логику (в React 19.2+ для этого есть `useEffectEvent`).
3. **Cleanup обязателен для всего, что подписывается или запускается.** Он должен полностью отменять действие эффекта. Эффект обязан переживать цикл «подключился → отключился → подключился»: если после двух вызовов поведение отличается от одного, в эффекте ошибка. Двойной запуск в Strict Mode не «лечим» флагом в `ref`.
4. **Не вызываем `setState` синхронно в теле эффекта в ответ на другое состояние.** Это лишний рендер, и такой код находит правило `react-hooks/set-state-in-effect`. `setState` допустим в колбэках подписок, таймеров и ответов (они срабатывают позже). Единственное исключение — замер DOM в `useLayoutEffect`, показанный выше: правило отключаем точечно и с причиной.
5. **`useLayoutEffect` — только для замера и правки DOM до отрисовки.** Во всех остальных случаях используем `useEffect`.
6. **Функция эффекта не может быть `async`:** она вернёт Promise вместо функции очистки. Асинхронную работу выносим во вложенную функцию.

   ```ts
   // ❌
   useEffect(async () => {
     await doWork();
   }, []);

   // ✅
   useEffect(() => {
     const run = async () => {
       await doWork();
     };

     run();
   }, []);
   ```

7. **Не кладём в зависимости объекты и функции, которые создаются заново на каждом рендере,** без необходимости. Новая ссылка запускает эффект при каждом рендере. В зависимости указываем примитивные значения (см. ADR 7, раздел про объект параметров хука).

##### Обоснование

**1. Эффект запускается после отрисовки**

Любое состояние, поставленное в эффекте, приводит ко второму рендеру. Значение, вычисленное в рендере, появляется сразу и без лишней перерисовки.

**2. Обработчик события знает, что именно произошло**

В обработчике понятна причина: пользователь кликнул, отправил форму, ввёл значение. В эффекте остаётся только «изменилось состояние», и причину приходится угадывать по флагам вроде `isSubmitted`.

**3. Меньше цепочек и неявных зависимостей**

Каскад из эффектов, каждый из которых ставит состояние для следующего, невозможно прочитать сверху вниз. Вычисление в рендере и обработчики выполняются в понятном порядке.

**4. Готовые инструменты надёжнее ручных**

RTK Query решает гонки, кэш, отмену и ошибки. `useSyncExternalStore` гарантирует согласованное значение внешнего источника. Писать это вручную в эффекте значит повторять уже решённые ошибки.

**5. Совместимость со Strict Mode и React Compiler**

Эффект, который корректно подключается и отключается, не ломается при двойном запуске и не мешает компилятору оптимизировать компонент.

#### Контроль

```js
// eslint.config.js (фрагмент; правила входят в eslint-plugin-react-hooks, названия сверьте с вашей версией)
rules: {
  'react-hooks/exhaustive-deps': 'error',
  'react-hooks/set-state-in-effect': 'error',
},
```

Отключение этих правил допустимо только точечно (`eslint-disable-next-line`) и обязательно с причиной.

#### Последствия

- Меньше лишних рендеров, цепочек эффектов и гонок.
- Код проще читать: причина каждого действия видна в обработчике или в вычислении.
- Компоненты корректно работают в Strict Mode и совместимы с React Compiler.
- Нужно знать альтернативы эффекту (`key`, вычисление в рендере, обработчики, RTK Query, `useSyncExternalStore`) и применять их до того, как рука потянется за `useEffect`.
- Часть задач (замер DOM, сторонние библиотеки) всё равно требует эффекта, поэтому правила его написания (cleanup, честные зависимости) остаются обязательными.
