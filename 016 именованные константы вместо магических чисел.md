### 16. Именованные константы вместо «магических» чисел

#### Контекст

Число в формуле без имени ничего не говорит о себе: что оно означает, в каких единицах измеряется, откуда взято и что будет, если его изменить. Выражение `(valueC * 9) / 5 + 32` понятно тому, кто помнит формулу Фаренгейта, а `0.33 * vaporPressure - 4.0` или `p >= 1022` непонятно никому без поиска в интернете. Такое число легко «исправить» неправильно, а если оно встречается в двух местах, значения со временем расходятся.

#### Решение

Число, смысл которого не очевиден из контекста, получает имя. Имя пишется в `UPPER_SNAKE_CASE` (ADR 1) и называет величину вместе с единицей измерения: `FAHRENHEIT_AT_ZERO_CELSIUS`, `MIN_HEIGHT_PX`, `TREND_WINDOW_HOURS`. Имена вроде `NINE`, `COEFF` или `VALUE_1` ничего не объясняют, поэтому так не называем.

```ts
// ❌ что такое 1.8 и 32?
const toFahrenheit = (valueC: number) => valueC * 1.8 + 32;

// ✅ формула читается как текст
const toFahrenheit = (valueC: number) => {
  const FAHRENHEIT_PER_CELSIUS = 1.8; // на столько °F растёт температура при росте на 1 °C
  const FAHRENHEIT_AT_ZERO_CELSIUS = 32; // 0 °C = 32 °F

  return valueC * FAHRENHEIT_PER_CELSIUS + FAHRENHEIT_AT_ZERO_CELSIUS;
};
```

##### Где объявлять константу

Выбираем самое близкое место, где её видят все, кому она нужна:

| Где используется число | Где объявляем |
| --- | --- |
| В одной функции | В начале этой функции |
| В нескольких функциях одного файла | В начале файла, без `export` |
| В нескольких файлах, а также настройки и словари значений | В `constants.ts` на ближайшем общем уровне (ADR 1) |

Для React-компонентов константы лежат в `constants.ts` компонента или в начале файла, чтобы не создаваться заново при каждой отрисовке.

##### Как записывать

- Формулу читаем как текст: промежуточные результаты тоже получают имена (`humidityShare`, `vaporPressure`), а не прячутся в длинном выражении.
- Рядом с константой короткий комментарий: единица измерения, источник формулы или причина такого значения.
- Составное значение пишем одним литералом с разделителями разрядов: `3_600_000`, а не `3600 * 1000`. Коэффициент записываем десятичной дробью: `1.8`, а не `9 / 5`.
- Таблицу порогов оформляем объектами с именованными полями, а не цепочкой `if` с голыми числами.

```ts
// ❌ какое давление считается ясной погодой и при какой тенденции?
if (p >= 1022) return 'clear';
if (p >= 1012) return 'partlyCloudy';

// ✅ пороги собраны в таблицу, у каждого есть имя поля
const STEADY_BANDS = [
  {minHpa: 1022, kind: 'clear'},
  {minHpa: 1012, kind: 'partlyCloudy'},
];
```

##### Что можно оставить без имени

- `0`, `1`, `-1` и `2`: начало отсчёта, шаг, «минус один», пара или половина (`width / 2`).
- Значение по умолчанию параметра (`decimals = 1`).
- Индекс массива (`parts[2]`).
- Значение свойства объекта с понятным именем (`min: 300`, `minHpa: 1018`).
- Числа в тестах: там значение входит в саму проверку.

#### Контроль

Правило ESLint предупреждает о числах без имени. Файлы `constants.ts` и тесты из проверки исключены.

```js
// eslint.config.js (фрагмент)
'@typescript-eslint/no-magic-numbers': [
  'warn',
  {
    ignore: [0, 1, -1, 2],
    ignoreDefaultValues: true,
    ignoreArrayIndexes: true,
    ignoreEnums: true,
    ignoreNumericLiteralTypes: true,
    ignoreTypeIndexes: true,
    enforceConst: true,
  },
],
```

Правило не видит числа внутри свойств объектов (`{length: 42}`), поэтому такие случаи проверяем на код-ревью.

#### Последствия

- Формулы и пороги читаются без поиска и догадок.
- Значение меняется в одном месте, и расхождений между копиями нет.
- Небольшие функции обрастают блоком констант в начале. Если их набралось больше десятка, выносим их в `constants.ts` или в таблицу.
- Имя нужно придумать, и это заставляет понять, что число означает.
